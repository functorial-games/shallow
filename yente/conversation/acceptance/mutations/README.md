# Compiled mutation acceptance

Four deliberately broken variants of the conversation core compiled successfully and were rejected by the separately implemented ai-ci executable oracle. The unmodified source compiled and passed the same oracle. `receipt.tsv` records process exits and the exact semantic failure labels.

These patches are negative test material. Apply one patch at a time to an isolated copy of the base source; never apply them to the implementation being delivered. Each patch changes one policy boundary and preserves the rest of the program.

| Patch | Deliberate defect | Expected oracle failure |
|---|---|---|
| `cross-session.patch` | The plan validator accepts current evidence from other sessions while leaving hypothesis-source validation intact | `response cannot cite another session's private evidence` |
| `stale-revocation.patch` | Revocation changes grant flags without invalidating evidence copied by an earlier authorized delivery | `revoked retelling excluded from future model request` |
| `shallow-withdrawal.patch` | Dependency closure returns root identifiers without descendants | `transitive hypotheses withdrawn` |
| `hypothetical-report.patch` | A hypothetical input is parsed as a report | `account kinds preserved` |

## Source and execution identities

The tested base consists of the nine Idriç modules in `examples/autogenerated/yente-conversation/`. `base-source-sha256.txt` identifies every module. The patches use repository-relative paths and have been checked against that base. No duplicate source tree or compiled binary is stored here.

- Canonical Idriç compiler source: `2bce7677f513d711875e978bd6f5ad28b9e54d58`.
- Backend: Chez, with the compiler's matching prelude, base, contrib, data, and support libraries.
- Frozen main candidate application SHA-256: `8e04ce846d0321b92199aba2506fdc598ab27b1731a7cbfdec68084a6343c187`.
- Independent oracle source: `isomorphisms/ai-ci`, `examples/autogenerated/yente-conversation/Accept.idric`.
- Tested oracle source SHA-256: `096cd471bee9745792b80d168da33e4607fc868aa819f002e00ca1f327471d87`.
- Tested oracle application SHA-256: `829f43a391e3283da8105ab7d402b3f3ad6e468cc044f56f686427dfbb0f26bd`.

The oracle source identified above includes the independent-support dependency test, the authorized shared-destination test, and optional demo-fixture validation. These mutation runs used its two-argument semantic-check interface; demo-fixture acceptance is a separate observation.

The base was independently rebuilt from its frozen modules. Each mutant was then built in a separate directory with the same compiler and libraries. The verified compiler operation was `idris2 -o yente-mutant Main.idric`, from that isolated source directory with the matching compiler environment. Compilation exit status alone was insufficient: each generated executable was present and actually launched by the oracle.

The oracle invocation is `yente-accept ABSOLUTE_CANDIDATE_EXECUTABLE ABSOLUTE_MATERIALS_DIRECTORY`. The materials argument identifies `yente/conversation/materials/` from this source tree. A reproduction must first verify the base hashes, apply exactly one patch, compile the altered source with the candidate's verified compiler setup, and run the oracle against the generated executable. Require the specific failure label and exit status 1; a crash, missing executable, parser failure, or unrelated infrastructure error is not a successful mutation rejection.

The unmodified base returned exit status 0 and `YENTE_AICI_ACCEPTANCE_OK`. All four mutants returned exit status 1 at their intended semantic checks. These are build-host process observations; they do not establish live-model judgment, hosted CI, production privacy, or physical-device behavior.

## Earlier runs excluded from the result

An initial dependency fixture gave every descendant direct support from the corrected evidence. Root-only invalidation consequently passed, exposing a weakness in the oracle. The fixture was corrected to give descendants separate independent support and require invalidation through their hypothesis dependencies. The final shallow-withdrawal mutant is rejected by that corrected test.

An earlier run overlapped a rebuild of the shared oracle application and terminated with a runtime memory error. That run is excluded. Final acceptance used immutable oracle and candidate paths, and every final mutant failure was an explicit semantic rejection rather than a crash.
